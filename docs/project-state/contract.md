## AUD-003 site instance contract

- CAP-008 is owned by `src/config/site-manifest.ts` and `src/config/site-server.ts`: one strict `src/config/site.json` contains public brand/UI, enabled/default languages, tool policy, origin and non-secret instance identity. Credentials belong only to each instance's environment. UI v1 import/export remains presentation-only; Studio updates/rollbacks preserve identity and policy and reject stale revisions.
- The supported translation set is en/zh. Enabled languages drive routing, locale links, alternates and sitemap. The default locale has no prefix; disabled language prefixes return 404. Branding drives public/auth/admin/mail text, metadata, icon and share image. A new site does not require editing common services.
- Closed tools have no visible/executable entry in any of the three presets or shared navigation. Tool/related model pages return 404; model list is empty. Authenticated new submissions return 403 / TOOL_DISABLED at both API and task-service boundaries, before input processing/provider configuration/credit hold. Missing provider credentials return 503 without charging. Disabling a tool preserves existing jobs, result/history access and financial settlement/refunds.
- Configuration changes require a local restart for a consistent full application snapshot (development HMR also updates files). Production requires rebuilding and restarting. The service boundary additionally reads current policy from disk, so a stale client cannot submit to a closed tool.
- CAP-009 is owned by `scripts/create-local-site.mjs`: source-only copy; separate PostgreSQL server/role/password and data directory, fresh auth/admin secrets, namespace for cookies and files, blank AI/payment/storage keys. Empty databases bootstrap from the original baseline SQL and then the same checksummed migrations. Existing databases are never reset.
- Aurora Notes is the recorded second instance at 3002, database 55433, Chinese default/only, summary entry enabled, video closed, no provider keys. Its generic `src/` code (except site.json), scripts and dependency lock matched the recorded AUD-003 candidate. AUD-004 updates the main template only; this second instance intentionally remains at its independent AUD-003 version. Its inherited template capability records do not constitute real-provider acceptance on that instance.
- Isolation evidence uses actual local HTTP/auth/database/file operations, including simultaneous own sessions, rejected foreign and renamed session cookies, cross-cluster credential rejection, same user/task IDs with separate ledgers/files, idempotent second-site grants and cross-site UI import. R2 namespace writes use an isolated adapter fixture; no real R2 deployment is claimed.
- Executable gates: `test-site-isolation.mjs`, `test-site-service-policy.ts`, `test-site-browser.mjs`, `test-site-production.mjs`, six retained suites and both builds. Usage and scope: parent `AUD-003-SITE-REUSE-GUIDE.md`. Subsequent implementation needs its own requested scope.

## AUD-004 local billing contract

Owner decision DEC-AUD004-LOCAL-20261101: “先完成本地接入与回归，正式部署后再做 Creem 真实测试”. Local QA is this task's completion gate; real Stripe/Creem acceptance and live activation remain separate. The Creem account currently has no completed store, products or keys; no Stripe test account is available.

- CAP-010 uses the same order/event/fulfillment/credit boundaries for all four configured providers. Each checkout freezes SKU, price, credits, environment/account and external product mapping. Persistent request IDs and leases own retries; browser redirects never mint.
- Subscription state lives in billing_subscriptions; every paid period is linked through billing_cycles to a normal paid order/fulfillment. User locks, unique receipts and exact period uniqueness serialize money. Another receipt for the same cycle, overlapping periods, wrong scope/price/currency/user or ambiguous legacy records do not mint. Database faults roll back the cycle/package/ledger/order together; verified events remain recoverable.
- Active/trial/checkout/return signals alone do not issue subscription credits. Only a verified, eligible paid invoice/transaction grants once. Scheduled cancellation preserves paid coverage and original credits; resume changes provider state and grants nothing. Ended subscriptions require a new subscription. Paused Stripe billing is not automatically resumed by this version.
- Package expiry for subscriptions is the original paid period end, including late historical invoices. Newer confirmed state wins over stale callbacks; expired/canceled state cannot receive an artificial grace day.
- Existing Stripe Customer and Creem subscription associations are used before metadata fallback. Exact old Creem grants for the same period are linked rather than reminted; subsequent cycles remain eligible. Current local DB had zero real subscriptions before this migration, so this is fixture-backed compatibility, not acceptance of arbitrary production history.
- Legacy Creem financial callbacks were removed from the auth plugin. Its webhook URL forwards to the same signature adapter; access/management compatibility endpoints use the common projection. Old checkout calls without a durable request ID are refused and point to the unified purchase page. Stripe authentication remains separate from billing.
- PayPal/Waffo flags, models, prices, paid/refunded records and refund rules remain preserved. New-provider automatic cash refunds are explicitly refused before reserving/debiting credits; Stripe/Creem refund/reversal acceptance is not claimed.
- Prices are the existing USD 5/100 and USD 15/350 one-time catalog; recurring amounts/credits retain pricing-user.ts. Per-channel external IDs use environment mappings and per-product UI eligibility. No coupons, seats, upgrade proration or historical price migration is silently treated as a full standard cycle.
- Migration 0009 is additive apart from expanding the provider constraint. It adds order kind/product snapshot and scoped subscription/period tables, retaining existing rows. The main Stripe SDK/API pin is 23.1.0 / 2026-10-28.endive; other accepted dependencies remain fixed.
- Gates: seven retained integration/API suites (including billing), browser/API auth and submit contract, production isolation, typecheck/build, security threshold and second-instance isolation. Provider fixtures use fake keys and mocked provider responses; no new real-provider calls. Configuration and deferred account gates: parent AUD-004-BILLING-GUIDE.md.
